# DeepSteam external Harness Host

This is DeepSteam's application-owned integration of the official DeepSeek Harness libraries, not the official Harness Desktop application. The pinned upstream source is `d743267388641bc76f17c45ce8b4c231aed1d32c`; dependencies are official npm `0.2.1-alpha.2` packages with Cordis `4.0.5-alpha.1`, locked by `package-lock.json`. Every installed official package's main JavaScript export and available runtime leaf exports are rebuilt from that preserved source using esbuild 0.28.2. The subprocess `./runner` export is compiled from its actual upstream `src/bin.ts`. `pinned-source-build.json` records exact package/export counts, source-input and output hashes. Unused generated Remote/Typert metadata remains the official npm artifact; the Host loads no Remote or Typert service. The original MIT license is retained alongside the integration and public runtime.

`scripts/harness_runtime.py start` starts the isolated profile and authenticated loopback service on port 3796. It creates private state below the selected storage root's `runtime/harness-state`, protects it with a current-user ACL, encrypts official authorization grants with Windows DPAPI, and strips inherited cloud keys. `/health` exposes only deployment facts. Other control routes require the internal bearer file; application gateway routes use separate per-connection guards. The official account plugin owns `/oauth/callback`, PKCE, origin checks, cancellation and credential invalidation. No password login, browser-cookie collection, or token-as-API-key translation exists.

The official Cordis context loads account authorization, account/API-key adapters, dynamically configured pi-ai routes, attachment normalization, durable JSONL sessions, tool registry and agent loop. There is no bundled Qwen route or onboarding assistant. API keys are request-scoped through DeepSteam's connection references and never persisted in task or session state.

Control endpoints are `/account/status`, `/account/login/start`, `/account/login/cancel`, `/account/signout`, `/models`, `/probe`, `/routes`, `/assistant` and `/shutdown`. The model gateway supports `/v1/models` and `/v1/chat/completions`, preserving text, reasoning, function calls, streaming, usage and inline images accepted by the official attachment service. JSON object/schema response formats become explicit model instructions and are validated with AJV before a success finish; malformed output ends with an error. Forced tool choices similarly become restricted declarations/instructions and are checked; forced tool fragments are buffered until validation. This is an application adapter, not a claim of native provider JSON-constrained decoding. Unsupported multiple completions and nondefault `top_p` fail explicitly. Remote image URL fetching is deliberately absent; callers must submit data images. A successful text probe on the image-capable model is followed by a tiny nonprivate red-left/blue-right image test; only the correct visual order enables vision.

Workspace and native-learning delegated tasks use this same Host, official workspace registry and JSONL persistence. A selected folder supplies the initial cwd; ordinary user-authorized tasks may also name other files and output directories. File, document, image, search, PowerShell, job, progress and inventory tools are available. `load_harness_tools` loads official subagent, skill, goal, schedule, browser, native computer or explicitly configured MCP tools on demand. Browser automation uses the product's independent Chromium with isolated profiles. Native computer tooling is Cua Driver 0.28.0; Playwright MCP is pinned to 0.0.80. No third-party MCP server is enabled by default.

File tool paths are canonicalized; application state/profile and known credential directories are protected from direct file-tool access. Document upload/browsing HTTP retains workspace confinement. Root `AGENTS.md` and official filesystem skills provide local task guidance. The filesystem observation policy preserves read-before-edit freshness. These checks are application boundaries, not an OS sandbox; authorized shell commands run with ordinary current-user OS permissions and must remain within the user's request.

The default authorized-task mode does not ask separately for each ordinary write/edit/terminal step already covered by the user request. The legacy `exact-action-once` option remains testable for restricted deployments. PowerShell uses official managed subprocess/jobs and strips inherited cloud credential variables. Cancellation reaches parent tasks, descendant agents and owned jobs. Credentials and unrelated external actions remain outside automatic task authorization.

The official token meter, basic compaction and model-free result pruner manage context. The source ledger separately persists complete paged inventories, exact delivered unit/character spans, pending ranges, per-file notes and output references. Catalog completion, extraction, delivery and semantic understanding are distinct. Oversized summaries are rejected with a request to save per-file notes, never silently truncated. Long-history summarization uses the task's selected model. Concrete model references and configuration revisions survive cold resume; changed model configurations require an explicit new selection.

`/execution-tasks` accepts owner-scoped idempotent work and supports event polling, cancellation and explicit resume. Native learning/mastery and subagent consults delegate through an internal authenticated portal bridge, never a separate CLI, SDK profile or ambient `.dsh`. Reconnection reuses task IDs. Interrupted tasks retain sessions but are not silently replayed, because a pre-crash write may already have happened. Continuation validates the same owner and workspace before reusing its session.

Workspace routes include `/workspaces`, `/workspaces/:id/sessions`, `/sessions/:id/events`, `/sessions/:id/turn`, `/sessions/:id/cancel`, `/approvals/:id` and membership-checked image `/sessions/:id/attachments/:id`. Events are normalized from real official session logs with monotonic cursors; progress, tool outcomes and approval decisions are not generated transcripts. `workspace-folders.json` contains only registered user-folder paths for uninstall exclusion, excluding private onboarding bootstrap workspaces.

`build_runtime.py` stages public code, dependencies and attribution only and refuses missing Windows runner, ripgrep, Koffi and PTY assets. The installer must never include `harness-state`, profiles, credentials, control tokens or session logs. The product starts and stops the Host as a local service. Tests distinguish the scripted model transport from real local filesystem/image/search/PowerShell execution; these fixtures make no cloud or local model inference requests.
